# Accessibility-Audit-Studio
The goal is to build more than a dashboard. A developer should be able to create an audit, evaluate a website's accessibility, document problems, track fixes, and generate a report that a team can act on.

Product overview

Audit management
Create audits for websites and manage them through their lifecycle.



Accessibility checks
Review keyboard navigation, color contrast, form labels, and focus behavior, with automated checks where possible.



Finding management
Record issues, assign severity, attach evidence, and track fixes.



Reports and progress
Summarize findings, monitor resolution progress, and export reports.



Primary user
A frontend developer, QA engineer, or accessibility specialist who needs to evaluate a website and coordinate accessibility fixes.
Suggested user roles
- Admin: Manages users, projects, and permissions.
- Auditor: Creates audits, runs checks, and records findings.
- Developer: Reviews assigned findings and updates their resolution status.
- Viewer: Views audit results and downloads reports.
For your first version, implement a single-user workflow. Add multi-user permissions after the core functionality works.



Feature roadmap
Build the application in these phases so that each phase produces something usable.
Phase 1

Project and audit management
Create projects, register websites, create audits, view audit history.


Phase 2

Accessibility testing
Run automated checks, inspect keyboard navigation, record manual checks.


Phase 3

Finding management
Severity, status, assignment, screenshots, comments and filters.


Phase 4

Dashboard and reports
Summary metrics, trends, report generation and export.


Phase 5

Engineering quality
Authentication, authorization, test coverage, CI/CD and deployment.
